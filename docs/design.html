ResumeFit AI — Software Design

Technical Approach

The essential model

ResumeFit AI is two small Python services behind a reverse proxy on one VPS:

  1. The application — a Streamlit page that also runs the analysis. It validates inputs, removes contact details, applies usage limits, runs an AutoGen agent team in-process, validates and scores the final report, and renders it. It is the only component that holds the OpenAI key.
  2. The tools service — a FastMCP server with three tools: extract text from an uploaded resume, normalise skill names, and render Markdown to PDF. It holds no secrets, has no internet egress, and is reachable only on a private Docker network. Untrusted file parsing therefore happens in a process that has nothing worth stealing.

Caddy terminates HTTPS for the public domain and overwrites the client-address headers with the connecting address; the application trusts only that header. There is no database, no separate API service, and no user account store.

flowchart LR
  V[Visitor browser] -- HTTPS --> C[Caddy reverse proxy]
  C -- HTTP + websocket, edge network --> A[Application: Streamlit page, analysis pipeline, AutoGen team]
  A -- MCP streamable HTTP, private network --> M[Tools service: FastMCP]
  A -- HTTPS --> O[OpenAI: moderation and chat]

How one analysis runs

A deterministic pipeline does everything that can be decided without a model before any paid call. It first takes a non-consuming admission lease (one slot per visitor, three overall, and a check that quota remains), so floods of requests cannot fan out into parsing or moderation work. Then come file checks, text extraction (through the tools service, in a killable worker process with a deadline), length limits, instruction-smuggling and plausibility checks, contact redaction, and moderation. Only then does the lease consume one analysis from the daily quota and the agent team start; it only ever sees redacted text wrapped in explicit data markers. The pipeline emits a sanitised timeline entry for every stage and tool call from the first moment, so the visitor sees progress within a second.

The team is an AutoGen SelectorGroupChat arranged as a hub: after every specialist turn the orchestrator speaks again and names the next specialist on a NEXT: <agent> line; a small selector function reads that line, so no extra model call is spent on speaker selection. Specialists reply with typed structured output (Pydantic models via output_content_type). The Resume Parser, JD Analyst, and Matcher can call the normalize_skills MCP tool. The run ends when the Report Writer answers, or when a message, time, or token limit trips.

After the team finishes, the pipeline validates the Report Writer's draft, computes the two skill-coverage rubric criteria and the total score itself, strips any active content from every string, renders Markdown, and asks the tools service for a PDF. An invalid draft gets exactly one standalone retry of the Report Writer, only if the single per-analysis token budget (shared by the team, tool reflection, and the retry) can still cover it. Every outcome becomes one structured log event and, for failures, a fixed plain-language message with a support ID. The model client and MCP sessions of an analysis are opened in one AsyncExitStack and always closed in finally.

Why this shape

  • It satisfies the assignment (orchestrator, five specialists, skill files, MCP tools, structured output) with the least moving parts the brief allows.
  • Decisions that must be predictable — rejection rules, quotas, the score arithmetic, sanitisation — live in plain functions that are unit tested, not in prompts.
  • A verified dependency fact forces two dependency sets: AutoGen's MCP adapter (autogen-ext 0.7.5) imports symbols that no longer exist in mcp 2.x, while FastMCP 4 requires mcp 2.x. The two containers already have separate images, so each keeps its own pinned set, and a cross-process contract test proves they interoperate (both protocol stacks were exercised together while preparing this design).

Evolution

Likely next steps — shared limits across processes, a model-based injection classifier, accounts — each have an obvious seam (the limiter, the guard functions, the access gate) and are deliberately not built now.

Drivers & Constraints

  • Cost and abuse on a public URL drive the order of the pipeline (all cheap checks first), the in-process limiter, and the per-run message, time, and token caps.
  • Personal data drives redaction before any OpenAI call, memory-only handling, content-free logs, a read-only container filesystem, and output sanitisation.
  • Instruction smuggling drives three layers: pattern rejection, data markers plus explicit rules in every skill file, and deterministic scoring so an injected "give 100" cannot change the arithmetic.
  • Untrusted files drive parsing inside the isolated tools container, in a killable worker process with a wall-clock deadline, at most two at a time, with page, size, and archive caps and no egress.
  • Assignment constraints fix the agent roster, skill files, MCP boundary, and structured output.
  • Simplicity rules out FastAPI, databases, queues, and accounts. Limits are in memory because there is one application process on one VPS.
  • Testability without a key requires dependency injection of the model client, moderation client, and tools gateway into the pipeline.
  • No local Docker means deployment correctness is argued by static tests and a manual post-deploy checklist.

Structure and Layers

Dependencies point inward, from I/O toward plain decision code:

  • Presentation — the Streamlit page. It derives the visitor key from the proxy's trusted header, runs the access gate, collects inputs, calls the pipeline, and renders results. It holds no business rules.
  • Orchestration shell — the analysis pipeline. It sequences the stages, owns the admission lease on the limiter and the per-analysis resource stack, runs the agent team, handles the token budget, retries, and failure categories, and emits timeline and log events.
  • Decision core — guard functions, limiter policy, report finalisation and rendering, timeline mapping, and the speaker-selection function. No network, no clock (time is passed in), no files except reading the bundled pattern catalogue and skill files at start-up.
  • Adapters — the MCP tools gateway, the OpenAI model-client factory, and the moderation adapter. Each is a thin wrapper with a small protocol so tests can substitute it.
  • Tools service — a separate process with its own core (extraction, taxonomy, PDF layout) behind the MCP tool functions.

Components

Streamlit page

app/streamlit_app.py with helpers in app/resumefit/ui.py. One column: title and one-line purpose; privacy notice (what is sent to OpenAI, what is redacted, nothing stored, link to OpenAI's API data policy); access-code form when configured; file uploader (type=["pdf","docx","txt"], 2 MB); job description text area with a live character count; "analyses left today"; Analyse button (disabled while running, via an on_click callback that sets running in st.session_state before the rerun that performs the work); an st.status container that receives timeline entries; the result sections; three download buttons; Start over.

All report strings pass through ui.escape_markdown before display; no call uses unsafe_allow_html. The score is shown as text ("72 / 100") plus a progress bar. The whole action handler is wrapped so any exception becomes the generic message with a support ID. Singletons (settings, limiter, access gate) are created with st.cache_resource. The visitor key is visitor_key(client_identity(st.context.headers, st.context.ip_address, settings), secret); the same key feeds the limiter and the access gate. Session state holds only unlocked, running, timeline, and outcome; Start over deletes them.

Analysis pipeline

app/resumefit/pipeline.py. run_analysis sequences the stages described in Key Flows. It takes the admission lease first and releases it in finally, emits pipeline timeline entries through the caller's on_event callback before and after every stage and app-side MCP call, streams team events as further entries, enforces a hard asyncio.timeout of the configured analysis timeout plus 15 seconds, performs the single report retry, maps every exception to a failure category, and writes exactly one analysis_finished log event. analyse builds the real dependencies from settings and calls run_analysis; the page calls analyse.

Resource lifecycle. Each analysis opens one contextlib.AsyncExitStack: the tools gateway (await stack.enter_async_context(deps.tools_factory()), which holds one McpWorkbench and one agent-tool session) and the model client (stack.push_async_callback(client.close) immediately after creation). The stack is closed in finally on success, failure, timeout, and asyncio.CancelledError (which is re-raised after cleanup), so no client or MCP session outlives its analysis or is shared across Streamlit sessions or event loops.

Token budget. One budget of MAX_TOTAL_TOKENS covers the team, tool-result reflection, and the report retry: all use the same per-analysis model client, and spent tokens are client.total_usage() (prompt plus completion). Every call is capped by max_tokens=MAX_OUTPUT_TOKENS_PER_CALL (default 4,000), so the team's TokenUsageTermination can overshoot by at most one call. Before the retry the pipeline estimates its cost as the retry prompt's characters ÷ 3 plus the per-call output cap; if the remaining budget is smaller, the retry is skipped and the outcome is report_invalid with retry_skipped.

Guard functions and moderation adapter

app/resumefit/guardrails/. Pure functions except moderation.py:

  • uploads.validate_upload(filename, data) — extension allow-list (.pdf, .docx, .txt), size ≤ 2,097,152 bytes, signature check: PDF starts with %PDF-; DOCX starts with PK\x03\x04; TXT must decode as UTF-8 (BOM allowed) and contain no NUL bytes. A signature that matches a different allowed type or no type is a mismatch.
  • text_checks.check_resume_length, check_job_description_length — the spec's bounds (300–20,000 and 200–10,000 characters after whitespace normalisation).
  • text_checks.find_smuggling(text) — normalises with NFKC, removes zero-width characters, collapses whitespace, and matches the case-insensitive regular expressions in injection_patterns.txt (one per line, # comments). Initial catalogue: override phrases ("ignore/disregard/forget … previous/above/all … instructions/prompts/rules"), prompt-exfiltration requests ("reveal/print/repeat … system prompt"), persona switches ("you are now", "from now on you", "act as … AI/assistant/system/ChatGPT"), role markers at line start (system:, assistant:, developer:), chat-template tokens (<|im_start|>, [INST], <<SYS>>, ### instruction), scoring demands ("give/rate/score this candidate/resume … 100/perfect/maximum"), and the pipeline's own data-marker strings. Returns the first matching pattern name or None.
  • text_checks.looks_like_resume, looks_like_job_description — count distinct cue groups (resume: experience/employment/work history, education, skills, projects, certifications, summary/profile; job description: responsibilities/what you will do, requirements/must have, qualifications, preferred/nice to have, about the role/team, experience, "we are looking"); pass at two or more groups.
  • pii.redact(text) → RedactedText(text, counts) replacing emails, phone numbers (9–15 digits with common separators, optional + country code, so years and ranges such as 2019–2023 are untouched), URLs (scheme, www., and bare linkedin.com/…, github.com/… style paths), and street addresses (house number + up to five words + a street suffix such as Street, Road, Avenue, Lane, Nagar, Marg), plus a six-digit postal code only when preceded by "PIN" or "Pincode". Placeholders: [EMAIL], [PHONE], [URL], [ADDRESS].
  • moderation.OpenAIModerator(client, model="omni-moderation-latest", timeout_s=10).check(texts) → ModerationVerdict(flagged: bool); any exception or timeout raises ModerationUnavailable.

Usage limiter and access gate

app/resumefit/limits.py. UsageLimiter(per_visitor_daily, global_daily, max_concurrent, per_visitor_concurrent=1) keeps, under one threading.Lock (Streamlit runs each session in its own thread): per-visitor (utc_date, started) counts, per-visitor admitted counts, the total admitted count, and the global (utc_date, started) count. try_admit(visitor, now) checks in this order — visitor already admitted or running, busy, global cap used up, visitor quota used up — and returns an AdmissionLease (admitted counts incremented, nothing consumed) or a Refusal(reason, resets_at). AdmissionLease.start(now) re-checks both daily counts and atomically consumes one of each, returning None or a Refusal. AdmissionLease.release() is idempotent and frees the admission slots whether or not start was called. remaining(visitor, now) supports the page counter. Entries for past dates are dropped lazily, so memory stays proportional to one day's visitors.

AccessGate(code, max_failures=5, lockout=timedelta(minutes=15)) compares with hmac.compare_digest and tracks failures per visitor key. When no code is configured, required is false and the page skips the gate.

Report model, scoring, and rendering

app/resumefit/schemas.py and app/resumefit/report.py. The model-facing Pydantic classes use only plain field types so OpenAI strict structured output accepts them; every count, range, and rubric rule is checked afterwards in finalize_report(draft, redactions, meta), which either returns a MatchReport or raises ReportValidationError(reasons). It computes the must-have and nice-to-have points, validates the three model-judged criteria, sums the score, and sanitises every string: HTML tags removed, Markdown images dropped, Markdown links reduced to their text, bare URLs replaced by [URL], control characters removed, whitespace collapsed, each field truncated to 600 characters. render_markdown(report) escapes Markdown control characters in all report text and emits the fixed section headings listed under Data Model. report_json(report) returns model_dump_json(indent=2).

External-service adapters

app/resumefit/adapters/. ToolsGateway(url, timeout_s=30) is an async context manager. __aenter__ starts a dedicated owner task that enters, through its own AsyncExitStack, one create_mcp_server_session(params) (initialized first) and one McpWorkbench(StreamableHttpServerParams(url=settings.mcp_url, timeout=30)); __aexit__ tells the owner task to close both and waits for it, also on cancellation. The owner task isolates the MCP client's anyio task groups, which cancel their host task when a transport task fails: an unreachable service therefore raises ToolsUnavailable in the caller, while a cancellation of the caller still propagates as CancelledError once the owner task has finished.

  • extract_resume_text(filename, data) calls the tool on the workbench with base64 content and returns ExtractResult (the 30-second timeout exceeds the tools service's 10-second slot wait plus 10-second deadline).
  • render_pdf(markdown, title) does the same and returns bytes or None.
  • skill_tools() returns [t for t in await mcp_server_tools(params, session=session) if t.name == "normalize_skills"], so agents cannot call the extraction or PDF tools and share the gateway's session.
  • Transport or protocol failures raise ToolsUnavailable.

models.create_model_client(settings) returns OpenAIChatCompletionClient(model=settings.openai_model, api_key=settings.openai_api_key, temperature=0.2, timeout=60, max_retries=2, max_tokens=settings.max_output_tokens_per_call); the caller owns close().

Configuration and observability

app/resumefit/config.py: a frozen dataclass Settings.from_env(environ) parsing and validating the variables in .env.example; a missing OpenAI key is a start-up error; __repr__ masks secrets. app/resumefit/observability.py: configure_logging(level) installs a JSON-lines formatter on stdout; log_event(name, **fields) accepts only an allow-listed set of field names (no free text); new_support_id() returns RF- plus eight Crockford base32 characters; visitor_key(ip, secret) returns the first 16 hex characters of HMAC-SHA256; client_identity(headers, remote_ip, settings) returns, when trust_proxy_headers is true, the stripped value of the single header named by client_ip_header (case-insensitive; default X-Real-IP, which Caddy overwrites), or the shared identity "proxy-unknown" when that header is missing, so omitting it cannot mint fresh identities; every other header, including X-Forwarded-For, is ignored. MCP tools service

mcp_server/resumefit_tools/. server.py creates FastMCP("resumefit-tools"), registers the three tools and GET /health, and main() runs mcp.run(transport="http", host="0.0.0.0", port=8000, stateless_http=True, allowed_hosts=<MCP_ALLOWED_HOSTS>). extraction.py detects the type from the signature (the caller's extension is advisory), enforces size and page caps, checks a DOCX's ZIP directory before parsing (at most 500 entries, at most 20 MB total uncompressed size, no entry with the encryption flag bit, and no entry that is itself a ZIP by name suffix or PK\x03\x04 signature), and extracts text (pypdf page text; python-docx paragraphs and table cells; UTF-8 text). worker.py runs every extraction in a fresh child process (multiprocessing spawn context; on Linux the child also sets RLIMIT_AS to 256 MB and RLIMIT_CPU to the deadline) behind an asyncio.Semaphore(MAX_CONCURRENT_EXTRACTIONS=2). A request waits at most 10 seconds for a slot (else busy); the parent waits for the result without blocking the event loop and, at the wall-clock deadline (EXTRACTION_TIMEOUT_SECONDS=10), kills the child and returns timeout. The event loop never parses, so /health keeps answering. Both values are environment-overridable. taxonomy.py loads taxonomy.json (about 150 canonical skills with categories and lower-case synonyms) once and maps each input to its canonical name, or to the trimmed input with category other. pdf_render.py lays out the Markdown subset with fpdf2 core fonts, transliterating common typographic characters and replacing other non-Latin-1 characters with ?. Tools log only name, duration, and result code.

Report retry rule. The single retry runs when the team produced a report draft that failed parsing or finalize_report, or when the team raised an error after the orchestrator's latest NEXT: line named report_writer, and all four specialist outputs were collected. The pipeline then runs build_report_writer(model_client) once as a standalone agent, on the same model client, with a task containing the four outputs as JSON and the validation reasons, provided the token-budget check passes (otherwise report_invalid with retry_skipped). A second failure ends in report_invalid. Limit terminations are never retried.

PDF failure. render_pdf returning None or raising sets pdf=None; the outcome is still success and the page shows the PDF-unavailable note.

Concurrency and lifecycle

Each Streamlit session runs its script in its own thread; the analysis runs with asyncio.run inside that thread and creates its own model client, MCP sessions, and AutoGen runtime inside one AsyncExitStack, so nothing async is shared between sessions and everything is closed in finally — including when the hard timeout fires or the task is cancelled (the CancelledError is re-raised after cleanup). The limiter and access gate are process-wide singletons guarded by a lock. A browser disconnect mid-run lets the run finish (bounded by the timeout) and releases the admission lease in finally. The admission lease is the only cross-session state.

Design Decisions

Run the team inside the Streamlit process

  • Decision: the page calls the pipeline directly; no FastAPI or worker queue. Alternatives: separate API service (more deployables, auth between services, no benefit for one VPS); background job queue (needs storage). Consequences: a slow analysis occupies one Streamlit script thread, which the concurrency cap bounds; horizontal scaling would need the limiter moved to shared storage. Revisit if more than one application instance is needed.

Separate dependency sets per container

  • Decision: app/requirements.txt pins AutoGen 0.7.5 with mcp>=1.11,<2; mcp_server/requirements.txt pins FastMCP 4.0.10 (which needs mcp 2.x). Local development uses .venv for the application and .venv-mcp for the tools service. Alternatives: one environment with FastMCP 2.x (conflicts with the requested FastMCP 4 and an older server API); patching AutoGen (fragile). Consequences: two test runs and two interpreters; a cross-process contract test is required. Revisit when autogen-ext supports mcp 2.x.

Hub-and-spoke selector with a parsed delegation line

  • Decision: SelectorGroupChat whose selector_func returns the orchestrator after every specialist and otherwise the agent named on the orchestrator's NEXT: line. Alternatives: model-based selection (an extra paid call per turn, less predictable); RoundRobinGroupChat or a fixed Python sequence (no orchestrator decision, weaker fit to the assignment); Swarm hand-offs (more prompt surface). Consequences: about 11 model calls per analysis and deterministic tests; the orchestrator still decides order, re-asks, and completion.

Deterministic pre-processing before any agent

  • Decision: extraction, guards, redaction, and moderation run in the pipeline before the team; agents receive only redacted text and only the normalize_skills tool. Alternative: let the Resume Parser call the extraction tool (raw contact details would reach the model, and binary content cannot travel through model context). Consequence: the MCP extraction and PDF tools are called by application code, not by agents.

Typed outputs with app-side validation and scoring

  • Decision: every specialist uses output_content_type; the pipeline computes the coverage criteria and total and validates counts and ranges, retrying the Report Writer once. Alternatives: trust the model's total (not transparent, manipulable); put ranges into the model schema (risks strict-mode rejection). Consequences: injected "give 100" instructions cannot change coverage arithmetic; model-judged criteria stay bounded.

In-memory usage limits keyed by proxied client address

  • Decision: a lock-protected in-process limiter keyed by an HMAC of the address in the single header Caddy overwrites (CLIENT_IP_HEADER, default X-Real-IP), trusted only when TRUST_PROXY_HEADERS=true (the application port is unpublished, so only Caddy can reach it). A non-consuming admission lease is taken before any parsing; quota is consumed at team start. Alternatives: Redis or SQLite (a stateful dependency the spec excludes); cookies (trivially cleared); the last X-Forwarded-For entry (correct only while Caddy's default forwarding holds; an explicit overwrite is simpler to test). Consequences: limits reset on restart; visitors behind one NAT share a quota; the global daily cap bounds address rotation.

Extraction in a killable worker process

  • Decision: the tools service parses each file in a fresh spawned child process with a wall-clock deadline and kills it on expiry; at most 2 run at once. Alternatives: parse in a thread (cannot be stopped; a hostile file pins a core and memory until it finishes); a ProcessPoolExecutor (a hung worker cannot be killed individually). Consequences: about 0.3 s process start-up per extraction; the event loop and /health stay responsive; worst-case CPU is bounded by 2 workers and the container's cpus limit.

PDF rendering in the tools service from Markdown

  • Decision: the application renders Markdown (it owns the schema) and the tools service converts that Markdown subset to PDF. Alternatives: send report JSON to the tools service (duplicates the schema across packages); generate PDF in the application (adds a layout dependency next to the secret-holding process). Consequences: Latin-1 core fonts only; non-Latin characters degrade to ?.

Heuristic smuggling detection now, classifier later

  • Decision: a maintained regex catalogue with rejection, data markers, and skill-file rules; no second model call. Alternative: an LLM guard call per input (cost, latency, and its own injection surface). Consequence: novel phrasing can pass the first layer; the live red-team check measures the second layer.

Risks & Trade-offs

  • Test double drift from the real OpenAI API. The replay client does not prove that OpenAI accepts our strict schemas, formats tool calls the same way, or reports usage the same way; the fake moderation client does not prove real category behaviour. Mitigation: plain schemas, the optional live real-dependency test before every release, and recorded live evidence. Remaining risk: behaviour between live runs. Strengthen by scheduling the live test weekly if the service sees real traffic.
  • MCP library drift. autogen-ext 0.7.5 breaks with mcp 2.x; an unpinned upgrade would break the application at import. Mitigation: exact pins, the cross-process contract test, and the dependency decision above.
  • Residual prompt injection. Novel phrasing can pass the catalogue. Mitigation: data markers, skill rules, no dangerous tools, deterministic coverage scoring, sanitised output, live red-team check. Remaining: an injected instruction could bias the model-judged criteria (at most 45 points) or text. Strengthen with an LLM classifier if abuse is observed.
  • Names and employers reach OpenAI. Redaction covers contact details only; the notice says so. Name redaction would damage the analysis.
  • In-memory limits. Restarts reset quotas; shared addresses share quotas; rotating addresses bypass per-visitor quotas up to the global cap; forged headers cannot, because Caddy overwrites the one trusted header. Accepted for one VPS; the global cap and OpenAI account limits bound cost.
  • Malicious or slow documents. Parser bugs, decompression bombs, or files that parse for minutes. Mitigation: parsing only in the tools container (no secrets, no egress, read-only, 1 CPU and 512 MB limits, non-root), in a killable worker process with a 10-second deadline and at most 2 at a time; size, page, entry-count, expansion, encryption, and nesting caps; hostile fixtures. Remaining: a burst of slow files can make extraction busy for about 20 seconds; admission (3 overall) bounds how many arrive.
  • Leaked clients and sessions. A model client or MCP session left open after a timeout or cancellation would accumulate across Streamlit reruns and exhaust sockets or memory. Mitigation: one AsyncExitStack per analysis closed in finally; the lifecycle test covers success, timeout, cancellation, and errors.
  • Deployment unverified locally. Compose, Dockerfiles, Caddy, read-only Streamlit, and websocket proxying cannot be run on the development machine. Mitigation: static tests, the CI Docker job (docker compose config and both image builds), and the smoke checklist at first deploy; runtime evidence comes only from CI and the VPS. Specific watch items: Streamlit writing under HOME with a read-only root (fallback: a small writable tmpfs is already mounted at /tmp with HOME=/tmp), and FastMCP allowed_hosts matching the mcp:8000 Host header.
  • No script CSP. Streamlit needs inline resources, so only frame-ancestors is set; output sanitisation and never enabling unsafe HTML carry the XSS defence.

Trade-offs accepted. Two virtual environments for a simpler, isolated tools service; Latin-1 PDFs; English-only heuristics; a Report Writer agent that mostly assembles earlier outputs (kept because the assignment asks for it). Escalate review depth if accounts, stored resumes, payments, or agent actions on external systems are added.
